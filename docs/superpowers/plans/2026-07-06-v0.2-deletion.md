# SwipeSort v0.2 — Real Deletion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Prerequisite:** v0.1 tagged and trusted. `PhotoLibraryProviding`, `SwipeSessionModel`, `DecisionQueue`, `DryRunMode`, `PhotoKitLibrary` all exist.

**Goal:** Turn the in-memory `.delete` decisions from v0.1 into actual PhotoKit deletions — batched into a single system prompt at session commit — with a review-before-commit list, iCloud download progress indication, and safe rollback via `DryRunMode`.

**Architecture:** Extend `PhotoLibraryProviding` with `commitDeletions(_:)`. Add a `ReviewCommitView` that shows the pending-delete list before firing the system alert. Wire `PHPhotoLibrary.performChanges` on the real backend; the mock records the batch for tests to assert on.

**Tech Stack:** Same as v0.1. Adds `PHPhotoLibrary.performChanges`, `PHAssetChangeRequest.deleteAssets`, `PHImageRequestOptions.progressHandler`.

## Global Constraints

- All v0.1 global constraints apply.
- **`DryRunMode.isEnabled` defaults to `true`** (from UserDefaults). Task 3b adds a hidden debug menu — long-press the app title bar in the review screen — that flips the persisted flag. No recompile needed. A red banner appears whenever the flag is off so real deletions are visually distinct from dry runs.
- **One system prompt per session.** Never call `deleteAssets` per-swipe.
- **Deletion fires only on explicit "Delete" tap in `ReviewCommitView`.** No auto-commit on screen close, no auto-commit on session finish. Exiting the swipe screen mid-session preserves the pending queue in memory (v0.2 scope — persistence lives in v0.3). Sheet dismissal by swipe-down goes back to swiping, never to deletion.
- Cancellation (`PHPhotosError.userCancelled`) is expected, not an error state.
- iCloud download progress must be visible in the UI — hidden downloads that block the swipe are unacceptable.

## Research References

- Deletion API contract: `docs/RESEARCH.md` §2.2 (always-prompts, single-batch, `PHPhotosError.userCancelled`).
- iCloud download: §2.3 (`isNetworkAccessAllowed`, `progressHandler` on background queue).
- Composite media atomicity: §2.4 (Live Photos, RAW+JPEG delete together; bursts are separate assets).

## Task 2: Implement `commitDeletions` in `PhotoKitLibrary`

**Files:**

**Interfaces:**
- Consumes: `CommitResult`, `AssetIdentifier`, `DryRunMode` (Task 3 adds logging helper).

**No unit tests.** This wraps the real PhotoKit alert. Verified by smoke test (Task 6).

- [ ] **Step 1: Implement**

Add to `PhotoKitLibrary`:

```swift
func commitDeletions(_ identifiers: [AssetIdentifier]) async -> CommitResult {
    guard !identifiers.isEmpty else { return .success(affectedCount: 0) }

    if DryRunMode.isEnabled {
        DryRunMode.log("Would delete \(identifiers.count) asset(s): \(identifiers.map(\.rawValue))")
        return .success(affectedCount: identifiers.count)
    }

    // Resolve identifiers to PHAssets via fetchAssets(withLocalIdentifiers:).
    let rawIds = identifiers.map(\.rawValue)
    let fetched = PHAsset.fetchAssets(withLocalIdentifiers: rawIds, options: nil)

    // Collect only assets that can actually be deleted.
    var deletable: [PHAsset] = []
    fetched.enumerateObjects { asset, _, _ in
        if asset.canPerform(.delete) {
            deletable.append(asset)
        }
    }

    guard !deletable.isEmpty else {
        return .failed(reason: "No deletable assets in batch (permissions or read-only).")
    }

    return await withCheckedContinuation { cont in
        PHPhotoLibrary.shared().performChanges({
            PHAssetChangeRequest.deleteAssets(deletable as NSFastEnumeration)
        }, completionHandler: { success, error in
            if success {
                cont.resume(returning: .success(affectedCount: deletable.count))
                return
            }
            if let ns = error as NSError?, ns.domain == PHPhotosErrorDomain,
               ns.code == PHPhotosError.userCancelled.rawValue {
                cont.resume(returning: .cancelledByUser)
                return
            }
            cont.resume(returning: .failed(reason: error?.localizedDescription ?? "unknown"))
        })
    }
}
```

```swift
import Foundation
import os

/// Global kill-switch for destructive PhotoKit operations, persisted in UserDefaults.
/// Default is `true` (safe). A debug-menu UI toggle (v0.2 Task 3b) flips this at runtime.
enum DryRunMode {
    static let defaultsKey = "swipesort.dryRun"

    static func isEnabled(defaults: UserDefaults = .standard) -> Bool {
        guard let raw = defaults.object(forKey: defaultsKey) as? Bool else { return true }
        return raw
    }

    static func setEnabled(_ value: Bool, defaults: UserDefaults = .standard) {
        defaults.set(value, forKey: defaultsKey)
    }

    static var isEnabled: Bool { isEnabled() }

    private static let logger = Logger(subsystem: "com.harshalpatil.SwipeSort", category: "DryRun")

    /// Records an intended destructive action without executing it.
    static func log(_ message: String) {
        logger.notice("[DRY-RUN] \(message, privacy: .public)")
    }
}
```

```swift
var pendingDeletions: [AssetIdentifier] {
    queue.decisions.compactMap { decision in
        if case .delete(let id) = decision { return id }
        return nil
    }
}

func commitDecisions() async -> CommitResult {
    let ids = pendingDeletions
    guard !ids.isEmpty else { return .success(affectedCount: 0) }

    phase = .committing
    let result = await library.commitDeletions(ids)
    switch result {
    case .success:
        // Wipe delete decisions from queue; keep decisions stay.
        queue.removeDeletions()
        phase = .finished
    case .cancelledByUser, .failed:
        phase = .finished  // caller decides whether to reopen
    }
    return result
}
```

```swift
import SwiftUI

/// Sheet shown before the system delete prompt. Lists every asset the user
/// marked for delete so they can undo individual items before committing.
struct ReviewCommitView: View {
    let model: SwipeSessionModel
    let onCommit: () async -> Void
    let onDismiss: () -> Void

    var body: some View {
        NavigationStack {
            List {
                Section {
                    Text("You marked \(model.pendingDeletions.count) photo(s) for deletion.")
                        .font(.headline)
                    if DryRunMode.isEnabled {
                        Label("Dry-run mode is ON. Nothing will actually be deleted.", systemImage: "shield.lefthalf.filled")
                            .foregroundStyle(.orange)
                            .font(.footnote)
                    }
                }

                Section("Assets") {
                    ForEach(model.pendingDeletions, id: \.rawValue) { id in
                        Text(id.rawValue)
                            .font(.system(.body, design: .monospaced))
                            .lineLimit(1)
                            .truncationMode(.middle)
                    }
                }
            }
            .navigationTitle("Review")
            .toolbar {
                ToolbarItem(placement: .cancellationAction) {
                    Button("Back to swipe") { onDismiss() }
                }
                ToolbarItem(placement: .confirmationAction) {
                    Button(DryRunMode.isEnabled ? "Log (dry-run)" : "Delete") {
                        Task { await onCommit() }
                    }
                    .tint(.red)
                    .disabled(model.pendingDeletions.isEmpty)
                }
            }
        }
    }
}
```
